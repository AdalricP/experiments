REST API

Script in. STEP out.

Build a part, save it as a version, download the STEP. Three calls.

# 1 · build (stateless): summary + scene, nothing stored
curl -s https://api.voncad.dev/v1/build \
  -H "Authorization: Bearer $VONCAD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"script": "from build123d import *\nparams = {\"w\": 40}\nresult = Box(params[\"w\"], 30, 6)", "params": {"w": 60}}'

# 2 · save it as a document; the response holds version.id
curl -s https://api.voncad.dev/v1/documents \
  -H "Authorization: Bearer $VONCAD_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "plate", "script": "from build123d import *\nresult = Box(60, 30, 6)"}'

# 3 · export
curl -s https://api.voncad.dev/v1/versions/$VERSION_ID/export/step \
  -H "Authorization: Bearer $VONCAD_KEY" -o plate.step
import os, requests

API = "https://api.voncad.dev"
H = {"Authorization": f"Bearer {os.environ['VONCAD_KEY']}"}

script = """
from build123d import *
params = {"w": 40, "h": 30, "t": 6}
result = Box(params["w"], params["h"], params["t"])
"""

# 1 · build (stateless)
r = requests.post(f"{API}/v1/build", headers=H,
                  json={"script": script, "params": {"w": 60}}).json()
print(r["ok"], r["summary"]["volume"])

# 2 · save as a document → version
doc = requests.post(f"{API}/v1/documents", headers=H,
                    json={"name": "plate", "script": script}).json()
vid = doc["version"]["id"]

# 3 · export STEP
step = requests.get(f"{API}/v1/versions/{vid}/export/step", headers=H)
open("plate.step", "wb").write(step.content)
const API = "https://api.voncad.dev";
const H = { Authorization: `Bearer ${process.env.VONCAD_KEY}`, "Content-Type": "application/json" };

const script = `from build123d import *
params = {"w": 40, "h": 30, "t": 6}
result = Box(params["w"], params["h"], params["t"])`;

// 1 · build (stateless)
const built = await fetch(`${API}/v1/build`, {
  method: "POST", headers: H, body: JSON.stringify({ script, params: { w: 60 } }),
}).then(r => r.json());
console.log(built.ok, built.summary.volume);

// 2 · save as a document → version
const { version } = await fetch(`${API}/v1/documents`, {
  method: "POST", headers: H, body: JSON.stringify({ name: "plate", script }),
}).then(r => r.json());

// 3 · export STEP
const step = await fetch(`${API}/v1/versions/${version.id}/export/step`, { headers: H });
await require("fs/promises").writeFile("plate.step", Buffer.from(await step.arrayBuffer()));

Questions

The short answers.

Is it really build123d?

Yes. Your script runs against stock build123d on OpenCascade. Anything that works locally works here, within the sandbox: allowed imports are build123d, bd_warehouse, numpy, math and the standard numeric modules. No file or network access.

Can I import STEP?

Yes. POST /v1/import takes STEP, BREP or STL and returns a document with stable face ids, ready to measure, section, render or modify.

Is my code private?

Documents are private to your API key on every plan. Each build gets an unguessable version id that works as a share link, so only people you give it to can view or export it. Scripts run in isolated forked workers with memory and CPU limits, and nothing is shared between jobs.

Can I self-host?

Yes. It's open source. One command: docker run -p 8000:8000 voncad-cloud. Want a public URL for your agents? ./deploy/public.sh opens a Cloudflare quick tunnel.

How is it so cheap?

An open-source kernel, so no licence fees. Stateless workers forked from a warm process, so a build costs a fraction of a CPU-second. No per-seat pricing, because agents aren't seats.

Does it work with Claude, Cursor and ChatGPT?

Anything that speaks MCP over HTTP: Claude Code, Claude Desktop, Cursor, and ChatGPT connectors. For everything else there's the REST API and llms.txt.
