Voncad Cloud

A hosted build123d / OpenCascade kernel behind a REST API and an MCP server. Send a Python script, get back a B-rep with stable face ids, renders, analysis and exports.

Base URLhttps://api.voncad.devInteractive API explorer →
Start

Quickstart

Three steps: get a key, build a part, export it. Anonymous requests work too, on a small per-IP playground quota.

1 · Get a key

shell
curl -s -X POST https://api.voncad.dev/v1/keys \
  -H "Content-Type: application/json" -d '{"email": "you@company.com"}'
# → {"api_key": "vc_…", "plan": "free"}
export VONCAD_KEY=vc_…

Or use the form on the home page.

2 · Build a part

POST /v1/build is stateless: it runs the script and returns a summary and a scene. Nothing is stored.

shell
curl -s https://api.voncad.dev/v1/build \
  -H "Authorization: Bearer $VONCAD_KEY" -H "Content-Type: application/json" \
  -d '{"script": "from build123d import *\nparams = {\"w\": 40}\nresult = Box(params[\"w\"], 30, 6)", "params": {"w": 60}}'
# → {"ok": true, "logs": "", "summary": {"volume": 10800.0, "parts": [...]}, "scene": {...}}

3 · Save and export

Save the script as a document to get a version id, then download any format.

shell
VID=$(curl -s https://api.voncad.dev/v1/documents \
  -H "Authorization: Bearer $VONCAD_KEY" -H "Content-Type: application/json" \
  -d '{"name": "plate", "script": "from build123d import *\nresult = Box(60, 30, 6)"}' | jq -r .version.id)

curl -s https://api.voncad.dev/v1/versions/$VID/export/step -H "Authorization: Bearer $VONCAD_KEY" -o plate.step
curl -s "https://api.voncad.dev/v1/versions/$VID/render.png?view=iso" -o plate.png
Concepts

Documents, versions, params

Document. A named part or assembly. It owns a tree of versions. Documents are private to your API key; a version id is an unguessable share link for viewing and exporting.

Version. One build of one script with one set of params. Immutable. Each version has a parent, so history is a tree: branch from any version by passing it as parent. Analysis, renders and exports always point at a version id.

Params and configurations. A script may declare a top-level params = {"width": 40, ...} literal. Values sent as API params override those defaults before the script runs. param_schema on a version lists each one with its name, default and type. One script, many configurations.

Build steps. Every operation in a BuildPart is recorded. GET /v1/versions/{vid}/steps replays them, each with a plain-English description, the running volume and face count, and a scene you can load.

References: p0/f3

Every part, face and edge has a short id. The viewer, the REST API and the MCP tools use the same ids.

  • p0: the first part (assemblies have p0, p1, …).
  • p0/f3: face 3 of part 0.
  • p0/e7: edge 7 of part 0.

Numbers follow build123d's shape.faces() and shape.edges() order, so a script can say part.faces()[3] for the face the viewer calls p0/f3. Ids are stable for a given version; after an edit, use diff or the topology descriptors (type, area, centre, normal) to re-find a face.

Scene format v1

What the viewer draws, from GET /v1/versions/{vid}/scene and the scene field of a build. Arrays are base64 little-endian typed arrays. A face's triangles are contiguous, so start/count map a picked triangle back to its face id.

scene.json
{
  "format": "voncad-scene", "version": 1, "units": "mm",
  "bbox": { "min": [x, y, z], "max": [x, y, z] },
  "parts": [{
    "id": "p0", "name": "bracket", "color": "#d8d6d0",
    "positions": <b64 float32 xyz>, "normals": <b64 float32 xyz>, "indices": <b64 uint32>,
    "faces": [{ "id": "p0/f3", "type": "plane", "start": 120, "count": 2,
                "area": 12.5, "center": [..], "normal": [..] }],
    "edges": [{ "id": "p0/e7", "type": "line", "length": 10.0,
                "points": <b64 float32 xyz polyline> }]
  }]
}

Cylindrical, conical, spherical and toroidal faces also carry radius and axis.

Scripts

Script rules

Scripts are plain build123d Python, run in a sandbox: an AST check, then a forked worker with memory and CPU limits.

  • Output. Assign result = ..., or call show(a, b, ...) for an assembly (each argument becomes a part). Failing both, the last build123d shape or BuildPart in scope is used.
  • Params. Optional top-level params = {...} dict literal. API params override its values.
  • No I/O. No file, network, OS or introspection access: export_*/import_*, open, np.save/np.load, frames and dunders are rejected with a clear error. The server exports for you.
  • Imports. build123d, numpy, math, cmath, random, itertools, functools, operator, typing, dataclasses, enum, copy, collections, statistics, fractions, decimal, string, re.
  • Not allowed. File and network access, open, exec, eval, getattr/setattr, dunder attributes, relative imports.
  • Logs. Anything you print() comes back in logs.
  • Units. Millimetres.
bracket.py
from build123d import *

params = {"width": 60, "height": 40, "thickness": 6, "hole": 6.5}
w, h, t = params["width"], params["height"], params["thickness"]

with BuildPart() as bracket:
    with BuildSketch(Plane.XZ):
        with BuildLine():
            Polyline((0, 0), (w, 0), (w, t), (t, t), (t, h), (0, h), close=True)
        make_face()
    extrude(amount=w * 0.6, both=True)
    with Locations((w * 0.55, 0, t)):
        with GridLocations(w * 0.45, w * 0.6, 2, 2):
            Hole(params["hole"] / 2)

result = bracket.part
REST API

Reference

JSON in, JSON out, unless noted. Authenticate with Authorization: Bearer vc_.... The header is optional: without it you're on the anonymous playground quota, counted per IP. An OpenAPI schema is served at /openapi.json, and an interactive explorer at /api/docs.

Errors use HTTP status codes: 400 bad input, 401 bad key, 404 unknown id, 422 validation, 429 quota. A script that fails to build is not an HTTP error: you get 200 with ok: false, an error message and logs.

Build

POST/v1/build

Stateless build. Runs the script, returns a summary and a scene. Nothing is stored. Use it for fast iteration; save with /v1/documents when you want ids that last. links gives ready-made URLs for the scene, renders, report, explainer, exports and a shareable viewer.

FieldDescription
scriptbuild123d source. Required.
paramsOverrides for the script's params dict.
qualityTessellation quality: draft, normal (default) or fine. Geometry and exports are exact either way.

  "summary": {
    "parts": [{ "id": "p0", "name": "bracket", "volume": 27104.2, "area": 9811.6,

  "scene": { "format": "voncad-scene", … },
  "links": { "scene", "render", "render_grid", "report",
             "explainer", "step", "stl", "glb", "viewer" } }

Versions

GET/v1/versions/{vid}

Everything about a version: source, params and their schema, build status, logs and summary.

{ "id", "document_id", "parent", "script", "params",
  "param_schema": [{ "name": "width", "default": 60, "type": "number" }],
  "status", "error", "logs", "summary", "created" }
GET/v1/versions/{vid}/scene

Tessellated scene for a viewer. See scene format.

{ "format": "voncad-scene", "version": 1, "parts": [ … ] }
GET/v1/versions/{vid}/topology

Face and edge descriptors without the mesh. Small enough to put in a prompt. This is how an agent picks p0/f3.

{ "parts": [{ "id": "p0",
  "faces": [{ "id": "p0/f3", "type": "cylinder", "area": 204.2,
              "center": [..], "radius": 3.25, "axis": [0, 0, 1] }],
  "edges": [{ "id": "p0/e7", "type": "circle", "length": 20.4 }] }] }
GET/v1/versions/{vid}/steps

Build-step replay. One entry per operation, described in plain controlled English, with the running volume and face count and a scene URL for that state.

[{ "index": 3, "op": "Hole",
   "description": "Cut a Ø22 mm bore through the centre.",
   "volume": 74004, "faces": 7,
   "scene_url": "/v1/versions/v_41ab…/steps/3/scene" }]

Analysis

POST/v1/versions/{vid}/measure

Minimum distance between two references, plus the angle when both are planar or linear.

{ "a": "p0/f1", "b": "p0/f7" }
// →
{ "distance": 34.0, "angle_deg": 90.0, "a": {…}, "b": {…} }
POST/v1/versions/{vid}/section

Cut with a plane. Returns the section area and an SVG of the profile.

{ "origin": [0, 0, 5], "normal": [0, 0, 1] }
// →
{ "area": 1640.2, "svg": "<svg …>" }
GET/v1/versions/{vid}/mass?density=7.85

Mass properties. density in g/cm³ (7.85 steel, 2.70 aluminium, 1.24 PLA).

{ "volume", "area", "mass_g", "center_of_mass", … }
POST/v1/versions/{vid}/check

Design-for-manufacturing checks for a process: fdm, cnc or sheet. Findings reference face ids.

{ "process": "fdm" }
GET/v1/diff?a={vid}&b={vid}

Geometric diff between any two versions.

{ "volume_added": 1200.5, "volume_removed": 88.1,
  "faces_added": 6, "faces_removed": 2, "bbox_change": [20, 0, 0], "identical": false }
GET/v1/versions/{vid}/interference

Clash detection for assemblies: every pair of overlapping parts with the overlap volume and its centre.

{ "clashes": [{ "a": "p0", "b": "p1", "volume_mm3": 512.4, "center": [..] }], "ok": false }
GET/v1/versions/{vid}/bom?density=

Bill of materials: identical parts grouped with quantities, sizes and optional mass.

POST/v1/agent

Text-to-CAD. Describe a part; Claude writes the build123d program, the kernel builds it, Claude looks at the four-view render and fixes what is wrong (up to 4 rounds). Every round is a real version. Pass script to modify an existing program, or document_id to save rounds into a document. Needs an API key; enabled when the server has ANTHROPIC_API_KEY set (GET /v1/agent reports available).

{ "prompt": "NEMA 17 motor mount, 5 mm plate, slotted holes" }
# → {"ok": true, "version": {…}, "rounds": [{"version_id", "ok", "error", "note"}]}

Export & import

GET/v1/versions/{vid}/export/{fmt}

Download the model. fmt is one of step, stl, glb, 3mf, brep, obj, svg, dxf (SVG and DXF are 3-view drawings with hidden lines).

curl -s https://api.voncad.dev/v1/versions/$VID/export/step -o part.step
POST/v1/import

Multipart upload of a step/stp, brep or stl file. Returns a new document whose first version has stable ids.

curl -s https://api.voncad.dev/v1/import -F file=@housing.step \
  -H "Authorization: Bearer $VONCAD_KEY"
# → {"document": {…}, "version": {…}}
MCP

Streamable HTTP at https://api.voncad.dev/mcp. Tools mirror the REST API. Render tools return images, so the model sees the part.

Every job runs with a time limit (60 s by default) and a memory cap. Usage is metered in calls and compute milliseconds. Anonymous playground calls are rate-limited per IP. Check your usage with GET /v1/me. Over quota you get 429.

Self-hosting

Run it yourself

Open source, free to self-host. One container serves the API, the MCP server and this site.

shell
docker run -p 8000:8000 voncad-cloud
# → http://localhost:8000  (site, /v1, /mcp)

Need a public URL for a remote agent? This starts the server and opens a Cloudflare quick tunnel. No account needed.

shell
./deploy/public.sh
# → https://<random>.trycloudflare.com

Point this site at any server with ?api=https://your-host; it's remembered in this browser. ?api=reset clears it.
